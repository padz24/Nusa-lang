# Package Manager (Phase 30, v1.11.0; registry Phase 31, v1.12.0)

`nusa pkg` mengelola paket sumber-lokal: manifest, dependensi path,
lock file + checksum, build reproduksibel, dan kemas tarball.
Registry file-backed: publish/download/search/install (§ Registry).

## Manifest `nusa.toml`

```toml
[package]
name = "myapp"
version = "0.1.0"
compiler = "1.11.0"   # versi compiler minimum (opsional)
target = "aarch64-linux-android"  # opsional, bebas
features = ["net"]    # opsional, bebas
entry = "src/main.ns" # opsional (default main.ns, lalu src/main.ns)

[capabilities]        # v2.10.0 (semua default false; key asing ditolak)
filesystem = false    # file_read/file_write/file_exists
network = false       # tcp_*/dial (std.net/http)
process = false       # process_exit/env/cwd
environment = false   # dicadangkan
native = false        # extern fn + [link] — DIENFORCE pkg build

[dependencies]
greet = { path = "../libs/greet" }
future = "1.2.3"      # versi registry — diresolve via registry (Phase 31)
```

- Nama: `[A-Za-z_][A-Za-z0-9_]*`; versi: semver `M.m.p[-pre]`.
- Subset TOML: section, `key = "str"/int/true/false/["a"]`,
  inline-table `{ k = v }`, komentar `#`.

## Alur kerja

```sh
nusa pkg init myapp --dir app   # manifest + stub main.ns
nusa pkg add greet --path ../libs/greet
nusa pkg update                 # tulis nusa.lock (+ checksum)
nusa pkg build                  # -> target/myapp (NUSA_PATH otomatis)
./target/myapp
nusa pkg remove greet
nusa pkg publish --dry-run      # validasi + tarball dist/
nusa tree                       # graf dependensi (juga `pkg tree`)
nusa verify                     # verifikasi ulang checksum lock
nusa outdated                   # versi registry lebih baru
nusa audit                      # capability + checksum per paket
```

- `init [name] [--dir D]`: menolak bila `nusa.toml` ada; nama default
  = basename direktori.
- `add <name> (--path <dir> | <version>)`: target path HARUS paket
  (punya `nusa.toml` bernama sama).
- `update`: closure transitif path-deps (rekursif via manifest
  masing-masing) + registry-deps (perlu sumber registry:
  `--registry DIR`/`$NUSA_REGISTRY`; tanpa sumber → error dengan
  arahan). Konflik versi ganda / siklus langsung error.
- `build [-o out]`: cek minimum compiler; buat lock bila absen;
  TOLAK bila lock basi (checksum/daftar berubah — jalankan `update`);
  set `NUSA_PATH` ke dir dep (warisan env dipertahankan) lalu build.
  Mencetak `capabilities: …`; menolak `extern fn`/`[link]` tanpa
  `native = true` (Phase 59).
- `publish [--dry-run]`: butuh lock segar + build lolos; kemas
  `dist/<name>-<version>.tar.gz` (file terurut: manifest, lock,
  `*.ns`) + cetak sha256. Publish ke registry: `--registry DIR`
  (§ Registry di bawah).

## Lock file `nusa.lock`
```toml
# GENERATED by `nusa pkg` — do not edit.

[meta]
compiler = "2.12.0"   # pin eksak (Phase 61; beda/absen = basi)

[[package]]
name = "greet"
version = "0.1.0"
path = "../libs/greet"
checksum = "sha256:..."
```

- Path relatif terhadap manifest akar bila memungkinkan (portabel);
  absolut bila tak berhubungan.
- Checksum = SHA-256 (LLVM) atas `*.ns` + `nusa.toml` top-level paket,
  terurut nama — perubahan apa pun membuat lock basi.

## Reproduksibilitas

Build hanya memakai sumber yang dikunci (nama + versi + checksum).
`target/` dan `dist/` adalah artefak (tak di-checksum; masukkan ke
`.gitignore` bila pakai git).
Jaminan penuh + batas: `docs/repro-2.12.md`. Ringkasnya (v2.12.0):
resolusi deterministik (registry-order sama), lock mem-pin
compiler eksak (basi bila beda), tarball publish byte-deterministik
(sort/mtime/owner ternormalisasi + `gzip -n`), build `--fresh`
ulang di path sama byte-identik. Tidak dijamin lintas path
(path tertulis di IR), versi compiler, atau platform.

## Inspeksi read-only (v2.11.0, Phase 60)

Keempatnya tersedia top-level (`nusa tree`) maupun `nusa pkg tree`:

- `tree`: graf dependensi (`name version`, path-dep direkursi
  aman-siklus, registry-dep `req -> locked`); tanpa lock =
  registry tak-teresolusi (catatan).
- `verify [--registry DIR]`: manifest + tiap pin lock (path:
  checksum + isi aman; registry: tarball cache vs index +
  konten vs pin; SKIP jujur bila tak-tercache). rc != 0 bila FAIL.
- `outdated [--registry DIR]`: butuh lock; `name req: locked ->
  latest` bila registry punya lebih baru (+ penanda beyond-req).
- `audit`: capability + checksum closure (root, path-dep
  rekursif, manifest cache registry); `signatures: unavailable
  (checksums only)` — signing = follow-up. Advisory (rc 0).

Mirrors = beberapa registry via `--registry`/`$NUSA_REGISTRY`
(`:`-separated; pertama cocok menang). Offline = cache valid
berfungsi tanpa registry (dibuktikan `verify`). Resolusi
reproduksibel = lock + tulis terurut + `lockFresh`.

## Registry file-backed (v1.12.0, Phase 31)

Registry = direktori (lokal/shared; tanpa server/network):
`<reg>/index/<name>.toml` + `<reg>/packages/<name>-<ver>.tar.gz`.
Sumber registry: `--registry DIR` atau `$NUSA_REGISTRY` (boleh
beberapa, dipisah `:`; pertama yang cocok menang).

```sh
nusa pkg publish --registry ./reg   # validasi + tarball + index
nusa search calc --registry ./reg   # cari (substring nama)
nusa install calc                   # add (caret) + update
nusa install 'calc@^0.1.0'          # req eksplisit (persis/caret)
nusa publish --registry ./reg       # top-level ≡ pkg publish
```

- Requirement: `"1.2.3"` persis atau `"^1.2.3"` caret
  (`^1.2.3` → `>=1.2.3 <2.0.0`; `^0.2.3` → `<0.3.0`; `^0.0.3` →
  `=0.0.3`). Instalasi bare menyimpan caret atas versi termaksimum.
- Unduhan → cache `$HOME/.cache/nusa/registry/<reg>/<name>/<ver>/`
  + verifikasi ganda: hash transport tarball, lalu hash konten hasil
  unpack. Cache rusak sembuh otomatis dari registry.
- Lock mencatat `registry = "<asal>"`; build memverifikasi pin
  tanpa I/O registry bila cache hangat (hermetik); tamper cache
  terdeteksi (checksum ulang) dan disembuhkan.
- Republish versi sama: identik → idempoten (hash transport
  disegarkan — gzip tak deterministik); konten beda → ditolak.
- Paket berversi yang di-publish tak boleh punya path-deps
  (tak relokatable — publish dep-nya dulu sebagai versi).
- Keamanan: checksum dua lapis, integritas versi (tulis-sekali),
  verifikasi dependensi transitif + lock.

## Batasan Phase 30 (dilonggarkan Phase 31 untuk registry)

- Path-deps: versi = persis (konflik = error). Registry-deps:
  `"1.2.3"` persis atau `"^1.2.3"` caret (§ Registry) —
  `compiler =` minimum tetap berlaku untuk keduanya.
- Tanpa fitur selektif per-dep, tanpa profile release/debug,
  tanpa parallel build, tanpa yank.
